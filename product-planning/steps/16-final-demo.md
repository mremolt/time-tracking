# Step 16 – Help, acceptance and final demo (Milestone M2)

Phase 1b · Needs: all · Features: I-05
**Goal:** users get started without training, and the complete MVP runs locally and is presented to stakeholders. **End of the plan.**

**Read:** `context.md` (Journeys, Success criteria), `features.md`, `ux/README.md`, `ux/screens.md` (Help & guide).

## Features

| ID | Feature |
|----|---------|
| I-05 | Help/onboarding: in-app hints on the main screens and a short user guide in DE and EN for employees, project leads and backoffice |

## Scope
- **Help:** in-app hints; user guide using the design's screen names (Today / Heute, Day / Tag, Week / Woche, …) and screenshots of the final screens; Help & guide page.
- **Acceptance check** of every MVP feature in `features.md` against the demo data, incl. role and visibility tests.
- **UX acceptance** (success criterion "UX"): Today, Week, Dashboard match the mockups in light and dark; all other screens follow `ux/`; no a11y violations in any theme variant; every PDF follows `ux/pdf.md`, passes the PDF/UA validator, reads correctly in greyscale.
- **Demo installation:** fresh local install from the documented setup, loaded with the full demo data.
- **Demo script** walking through J1–J6 with each role, switching DE/EN.
- **Stakeholder demo** with backoffice, HR, payroll, project leads, management; feedback and decisions collected as input for the next stage (see "After this plan" in `plan.md`).

## Done when
Someone unfamiliar with the app records a full week using only the guide; the demo took place on a fresh local installation, all MVP features were shown, and the feedback is documented.
